# A real CLI for browser-use-rs

Date: 2026-08-27 · Status: **in progress** · Owner: Claude
Tracker: [`2026-08-27-rust-cli.track.yaml`](2026-08-27-rust-cli.track.yaml)

## Objective

Make the binary usable from a terminal, not only as an agent's MCP subprocess.
Closes [the silent-exit issue](../../issues/2026-08-27-binary-silently-exits-without-mcp-flag.md).

## Surface

```
browser-use-rs <TASK>          run the autonomous agent on TASK
browser-use-rs --mcp           MCP stdio server (unchanged)
browser-use-rs --help|--version

  -n, --max-steps N   step budget (default 10)
      --vision        attach screenshots to each prompt
      --model NAME    override BROWSER_USE_LLM_MODEL
      --headful       show the browser window
```

Anything unrecognized, or no arguments: usage on stderr, **exit 2**.

## Design

Everything needed already exists — `bu_agent::run_task(task, max_steps, actor,
llm, use_vision) -> AgentRunReport`, the same call the `retry_with_browser_use_agent`
MCP tool makes. The CLI is argument parsing plus wiring; no new capability.

- **No argument-parser dependency.** Five flags do not justify pulling in `clap`;
  manual parsing is ~60 lines and gives exact control of the help text. The
  workspace currently has no arg parser at all.
- **Parsing split from execution.** `Cli::parse(args) -> Result<Command>` is a
  pure function over a `Vec<String>`, so every flag combination is unit-testable
  with no process, browser, or network. `main.rs` stays a thin dispatch, per the
  repo rule about keeping command entry points thin.
- `--headful` sets `BROWSER_USE_HEADLESS=false` before the actor spawns, reusing
  the existing env plumbing rather than adding a parallel path.

## Test strategy (test-first)

Parser tests RED before implementation: `--mcp` wins; a bare task parses; flags
in any order; `--max-steps` rejects a non-number; unknown flag errors; empty args
errors; `--help`/`--version` are their own commands; a task that looks like a
flag (`-- --weird`) is still a task.

Then live: `--mcp` still lists 19 tools (no regression), and a real task runs
from the terminal against the configured gateway.

## Risks

- Touching `main.rs` risks the MCP path every agent depends on. Mitigated by
  keeping `--mcp` dispatch first and re-probing `tools/list` after.
- A CLI run launches a browser and spends tokens; that is the point, but the
  default step budget stays low (10).
